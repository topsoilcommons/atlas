These points are not like-for-like. The first two rows share the same 12 questions but sit on different corpora: the second row was re-accepted after Sprint W1 added 40 topics, which raised groundedness and lowered the correct source rate on one question. The set then grew from 12 to 17 questions on 2026-10-16, adding one question each for first aid, finance, nutrition, law, and medicine, so the 17 question rows measure a wider set than the 12 question rows. Citation enforcement landed on 2026-10-17: from that run on, a citation counts only if it names a file actually retrieved for the question, and an answer citing any unretrieved file earns no citation credit. The first enforced run reproduced the unenforced numbers exactly (0.804 / 1 / 0.765), which is the expected result for the extractive baseline answerer, since it cites exactly its retrieved sources. The named weak spot in the current rows is the finance question (`finance-budget`), which scores 0 of 3: the retriever answers it from economics.js instead of finance.js, so it is cited but not grounded and not from the correct source. That failure is kept in the committed report rather than edited away. The 2026-10-17 layer teams point ships the soil_microbes topic held out of the Sprint W2 merge: with the topic added and the old two file gate, this set reproduced the holdout regression (gardening soil question 2 of 3, groundedness 0.784), and the same numbers on the original 12 question subset were 0.806 with the gardening question at 2 of 3, matching the October 16 record. Widening the stage 1 file gate from two files to four restored the set exactly: every question's facts unchanged from the pre-topic run, groundedness 0.804 on this set and 0.833 on the 12 question subset, and the correct source rate rose to 0.824 because gardening.js is again among the files retrieved for its own question. The fix alone, without the topic, measured identically (0.804 / 1 / 0.824), so the wider gate does not depend on the new topic.

The 2026-10-17 evening point fixes the finance weak spot named above. Diagnosis first: stage 1 already ranked finance.js first for the finance-budget question, but stage 2 scored chunks by distinct literal keyword matches, and the question's plural "budgets" never matches the singular "budget" in the one finance.js chunk that carries all three facts (clay tablets; barley in, barley out; where the money goes). That chunk scored 2, tied with many chunks from other files, and lost the four answer slots to art.js and economics.js chunks that came earlier in corpus order. The change is plural stemming in `keywords()` in `run-eval.cjs` (a trailing s is stripped, with ss, us, and is endings guarded), so both retrieval stages match singular and plural forms. Measured in throwaway scripts before the edit, stage 2 stemming alone fixed finance (3 of 3; 0.863 / 1 / 0.882), stage 1 stemming alone lifted bbq-brisket (1 to 2 facts) and survival-priorities (1 to 3), and the combined change shipped here gives 0.922 / 1 / 1 with no question losing any fact; other measured variants (occurrence weighting, IDF weighting, chunk density, and stage 1 rank as a stage 2 tiebreak) either lost a fact on another question or scored lower. Finance-budget is no longer the weak spot. No question now scores below 2 of 3; the lowest tier is shared by beekeeping-varroa, bbq-brisket, geology-basics, and medicine-harvey at 2 of 3 each.

The 2026-10-18 evening point fixes the beekeeping weak spot named above. Diagnosis first: the Varroa chunk in beekeeping.js carries the "varroa" fact and scores 3 on the question's keywords, but eight other chunks inside the stage 1 gate also score 3 and sit ahead of it in corpus order, and the two chunks scoring 5 carry only the "queen" fact between them, so the four answer slots filled in corpus order gave frames and queen and never reached the Varroa chunk at rank 11. The change is in stage 2 of `retrieve` in `run-eval.cjs`: selection is now sequential, the highest distinct keyword score still wins each step, and a tie is broken by marginal keyword coverage, how many question keywords a chunk adds beyond the chunks already selected, with corpus order breaking any remaining tie as before. The honest reading of that number stands in the paragraph below: the baseline is a floor, and a floor at its ceiling says the eval set, not the tutor, is now the weak instrument. Growing the set is the queued work that follows.

The honest reading is that coverage grew but saturation did not break: each new question draws its three facts from a single passage whose wording the question closely tracks, the same shape as the existing 17, so the extractive baseline still reaches its ceiling on a wider set. The set is wider, not yet harder. Growing it further in this shape would keep measuring 1; the work that follows is questions whose facts are spread across more than one passage, or that test a misconception, so the set can separate a tutor that retrieves one matching passage from one that works across the atlas. There is still no lowest tier: all 22 questions score full facts.

Baseline mode is an extractive answerer over retrieved atlas passages. It is the floor: any real tutor configuration should beat it, and a drop here means retrieval or content changed for the worse.
